# SQLite schema

`data/raw/raw.sqlite` is the scrape store. It keeps one `raw_players` row per
player and run, with the original normalized stat rows in JSON columns. It is
append-only at the run level and is not the application query schema.

`data/sqlite/data.sqlite` is rebuilt from the latest completed raw rows and the
masters in `data/masters`.

## Published tables

- `players`: one row per player. It contains the original display names plus
  structured name, profile, birth date, career, and draft columns. `detail_json`
  retains the structured profile object for JSON export and fields that are not
  used in filtering.
- `batting_stats`: one row per player/team/season split. It contains all
  batting counting values available from NPB and the calculated rate metrics.
- `pitching_stats`: one row per player/team/season split. It contains all
  pitching counting values available from NPB and the calculated rate metrics.
- `leagues`, `teams`, `team_seasons`: stable master data used to resolve a
  displayed team name to `team_id` and `league_id`.
- `schools`, `player_schools`: normalized school relations extracted from the
  structured career field.

Career totals are intentionally not duplicated as another published table.
They are aggregate views over the season rows, and `npb-analysis` rebuilds
league-specific career totals in its own read database after synchronization.

`computed_json` is intentionally not part of the current published schema.
Metrics are stored in their typed season columns and are regenerated by the
calculation step. Player JSON remains an on-demand export, not a managed data
file.

## Derived metrics

All percentages are stored as proportions (`0.25` means 25%) and are rounded
to three decimal places. A metric is `NULL` when its required source values are
missing or its denominator is zero.

### Batting

- `batting_average`: `H / AB`
- `on_base_percentage`: `(H + BB + HBP) / (AB + BB + HBP + SF)` when SF is
  available; otherwise the recorded PA denominator is used
- `slugging_percentage`: `TB / AB`
- `ops`: `OBP + SLG`
- `iso`: `SLG - AVG`
- `walk_percentage`: `BB / PA`
- `strikeout_percentage`: `SO / PA`
- `babip`: `(H - HR) / (AB - SO - HR + SF)`
- `stolen_base_success_percentage`: `SB / (SB + CS)`
- `home_run_percentage`: `HR / PA`
- `extra_base_hit_percentage`: `(2B + 3B + HR) / H`
- `runs_per_plate_appearance`: `R / PA`
- `rbi_per_plate_appearance`: `RBI / PA`
- `walk_to_strikeout_ratio`: `BB / SO`

### Pitching

- `winning_percentage`: `W / (W + L)`
- `era`: `ER * 9 / IP`
- `whip`: `(H + BB) / IP`
- `strikeouts_per_nine`: `SO * 9 / IP`
- `walks_per_nine`: `BB * 9 / IP`
- `strikeout_to_walk_ratio`: `SO / BB`
- `hits_per_nine`: `H * 9 / IP`
- `home_runs_per_nine`: `HR * 9 / IP`
- `runs_per_nine`: `R * 9 / IP`
- `strikeout_percentage`: `SO / BF`
- `walk_percentage`: `BB / BF`
- `strikeout_minus_walk_percentage`: `(SO - BB) / BF`

Metrics such as wOBA, wRC+, WAR, and FIP are not persisted here because they
require season-specific league coefficients, park factors, or other context
that is not present in the NPB player pages.
